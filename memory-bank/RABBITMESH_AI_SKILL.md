# RabbitMesh AI Developer Skill Document 🐰🚀

This document is a "Skill Context" for AI agents and developers. It explains how to effectively build microservices using the `rabbitmesh-rs` framework. 

RabbitMesh is a "zero-port" macro-driven microservices framework that proxies all internal HTTP traffic through RabbitMQ directly mapped to static RPC functions. 

## 1. Importing the Framework (Git Dependency)
DO NOT try to import `rabbitmesh` from crates.io. It is an internal framework designed for rapid development. 

In your service's `Cargo.toml`, add the dependencies directly pointing to the `v0.2.3` branch of the framework on GitHub:

```toml
[dependencies]
# Core frameworks
rabbitmesh = { git = "https://github.com/hangsiahong/rabbitmesh-rs.git", branch = "v0.2.3" }
rabbitmesh-macros = { git = "https://github.com/hangsiahong/rabbitmesh-rs.git", branch = "v0.2.3" }

# Essential integrations
tokio = { version = "1.40", features = ["full"] }
serde = { version = "1.0", features = ["derive"] }
serde_json = "1.0"
```

## 2. Defining The Macro Service Structure
Because RabbitMesh heavily utilizes the `#[service_impl]` macro system to abstract boilerplate, the generated handler endpoints become **static methods**. Therefore, infused struct properties like `self.db` or `self.handler` are **NOT ACCESSIBLE**. 

**DO NOT WRITE:**
```rust
// WRONG! The #[service_impl] macro drops access to `self` in generated endpoints
pub async fn create_user(&self, msg: Message) { 
    self.db.create(...) 
}
```

**CORRECT - The Global State Pattern:**
You must use `std::sync::OnceLock` to hold the async Database/Handler memory references globally so the static endpoints can tap into it.

```rust
use std::sync::{Arc, OnceLock};
use rabbitmesh_macros::{service_impl, service_method};
use rabbitmesh::Message;
use serde_json::Value;

// 1. Define the Global State Lock
static HANDLER: OnceLock<Arc<MyServiceHandler>> = OnceLock::new();

// 2. Define the Empty Structural Service
pub struct MyService {}

// 3. Implement the macro wrapper
#[service_impl]
impl MyService {
    // Inject the handler safely at initialization
    pub fn new(handler: MyServiceHandler) -> Self {
        let _ = HANDLER.set(Arc::new(handler));
        Self {}
    }

    // 4. Define static REST endpoints mapping to RabbitMQ
    #[service_method("POST /api/v1/items")]
    pub async fn create_item(msg: Message) -> Result<Value, String> {
        let request: CreateItemRequest = msg.deserialize_payload()
            .map_err(|e| format!("Invalid request format: {}", e))?;

        // 5. Access the Global Lock explicitly
        let handler = HANDLER.get().expect("Handler not initialized");
        
        match handler.create(request).await {
            Ok(data) => Ok(serde_json::to_value(data).unwrap()),
            Err(e) => Err(format!("Failed to create: {}", e))
        }
    }
}
```

## 3. Initializing and Running Your Microservice
In your `main.rs`, simply initialize your configurations, connect your mock or real DB database, attach it to your service using `.new()`, and trigger the RabbitMesh RPC lifecycle binding:

```rust
use rabbitmesh::{MicroService, ServiceConfig};
use crate::service::MyService;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    // 1. Initialize your DB Handler connection (e.g. MongoDB, Postgres, Redis)
    let my_handler = MyServiceHandler::new("postgres://...").await?;
    
    // 2. Attach handler to your Macro proxy (Sets the Global OnceLock)
    let _service = MyService::new(my_handler);
    
    // 3. Connect the RPC RabbitMesh Core
    let config = ServiceConfig::new("my-service", "amqp://localhost:5672");
    let microservice = MicroService::new(config).await?;
    
    // 4. IMPORTANT: Register all bindings macro-generated by #[service_impl]
    MyService::register_handlers(&microservice).await?;
    
    // 5. Start the Zero-Port listener loop
    microservice.start().await?;
    
    Ok(())
}
```

### Useful Metadata Values
When implementing endpoints, the `msg: Message` parameter provides several built-in utilities:
* `msg.deserialize_payload::<T>()` - Safely unwrap json payloads into Strong Types.
* `msg.metadata.get("id")` - Retrieve URL parameters like `GET /users/:id` -> `msg.metadata.get("id")`.

### Common Failure Points to Avoid
1. The compiler warns about `self`: You forgot that endpoints are expanded generically statically. Map DB controllers to `HANDLER: OnceLock<T>`.
2. Gateway can't find your endpoint: Verify you've properly invoked `MyService::register_handlers()`.
3. RabbitMQ blocks/hangs forever: Make sure your logic does not block the executor for over 30s. Background heavy tasks to alternative channels asynchronously.

## 4. Full-Stack Frontend Integration (React/Vite/NextJS)
When integrating a frontend SPA (Single Page Application) with the RabbitMesh backend Gateway, always be aware of the following architectural rules:

### A. The CORS Requirement
The standard `create_auto_router` in `rabbitmesh_gateway` does NOT have CORS enabled. Web applications will throw a `Network Error` from Axios Preflight failures. 
You must explicitly inject a `tower_http::cors::CorsLayer` before serving the Axum gateway:
```rust
use tower_http::cors::CorsLayer;
// Create the auto-router...
let app = auto_router.layer(CorsLayer::permissive()); 
axum::serve(listener, app).await?;
```

### B. The Gateway Routing Path (Crucial Trap)
Because RabbitMesh statically maps REST paths directly into RabbitMQ RPC queues, the Gateway expects a very strict format to proxy the call. 
**Format:** `http://<gateway_url>/api/v1/{service_name}/{rust_macro_function_name}`

**The Generator Bug:** If you use the `@rabbitmesh/client-generator` node package, it currently has a bug where it generates paths using the raw declarative `path` string (e.g. `/api/v1/orchestrator-service/api/v1/jobs`), which will return a **404**. 
You must either:
1. Manually update the Frontend's Axios calls to hit the explicit function name (e.g. `axios.post('/api/v1/orchestrator-service/submit_job')`).
2. Correct the `client-generator` script dynamically. 

By following these rules, the mesh tunnel will cleanly forward HTTP headers -> Axum Gateway -> RabbitMQ Binary Payloads -> Rust Worker Nodes.
